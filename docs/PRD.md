# AutoSet AI - 프로덕트 요구사항 문서 (PRD)

## 1. 프로젝트 개요
- **프로젝트명:** AutoSet AI (오토셋 AI)
- **한 줄 소개:** Spring 기반의 운동(웨이트 & 유산소) 기록 및 분석 플랫폼
- **기획 배경:**
    - 헬스장에서 웨이트 트레이닝과 유산소 운동(러닝머신, 스텝밀 등)을 병행할 때, 운동 중 스마트폰에 수치를 일일이 입력하는 UI 조작은 높은 피로감을 유발합니다.
    - 기존 앱들은 정형화된 입력 인터페이스만 제공하며, 개인의 운동 볼륨과 유산소 지속 시간에 맞춘 유연하고 맥락 있는 피드백을 제공하는 데 한계가 있습니다.
- **해결 방안:**
    - **LLM을 이용한 자유 형식 자연어 파싱:** 웨이트(무게/횟수)와 유산소(시간/거리/속도)를 가리지 않고, 목소리 또는 텍스트 한 번으로 LLM이 분류하여 정형 데이터로 적재.
    - **통합 피트니스 리포트:** 주간 웨이트 볼륨(점진적 과부하)과 유산소 총 시간/소모 에너지를 취합하여 종합적인 운동 밸런스 피드백 실시간 제공.

---

## 2. 핵심 기능 요구사항

### ① AI 기반 다종 운동 일괄 텍스트 파싱
- 사용자가 입력한 자연어 기록을 Spring AI가 분석하여 운동 유형(`WEIGHT`, `CARDIO`)을 자동 판별하고 DB에 적재.
    - **웨이트 입력 예시:** *"벤치프레스 80kg 10회 3세트, 랫풀다운 50kg 12회 3세트"*
    - **유산소 입력 예시:** *"인클라인 러닝머신 속도 6 경사도 5로 30분, 천국의 계단 15분 레벨 8"*

### ② 통합 점진적 과부하 & 유산소 분석 리포트
- **웨이트 분석:** 주간 부위별 볼륨 추이, 추정 1RM(Epley 공식) 변화, 다음 세션 추천 중량 산출.
- **유산소 분석:** 주간 총 유산소 수행 시간, 평균 페이스/속도, 추정 소모 칼로리 계산.
- **개인화 코칭:** Spring AI을 통해 웨이트-유산소 비율 및 오버트레이닝 방지 가이드 제공.

### ③ 운동 세션 및 기록 CRUD
- 일자별 운동 세션(Session) 내에 복수의 웨이트/유산소 기록을 포함하여 관리.
- 데이터 히스토리 보존을 위한 Soft Delete(`deleted_at`) 적용.

## 4. 백엔드 엔지니어링 포인트
1. **도메인 중심 계층형 아키텍처 (Rich Domain Model & SOLID):**
    - 서비스 계층에 비즈니스 로직이 집중되는 현상을 방지하고, 1RM 추정 및 볼륨 연산 등 도메인 핵심 규칙을 엔티티 내부에 캡슐화하여 높은 응집도와 테스트 용이성 확보.
2. **다형성 도메인 모델링:**
    - 웨이트 세트(Weight, Reps)와 유산소 세트(Duration, Distance, Speed, Incline)의 서로 다른 특성을 JPA 상속 구조(또는 단일 테이블 전략/JSONB)로 설계하여 유연성과 쿼리 성능 확보.
3. **역할 분리 아키텍처 (Domain Logic vs LLM):**
    - 1RM 추정, 볼륨 계산, METs 기반 유산소 칼로리 연산은 빠른 Java 도메인 로직으로 처리.
    - 자연어 분류/파싱 및 종합 코칭 피드백 영역만 Spring AI로 위임.
4. **신뢰성 및 장애 격리:**
    - 외부 LLM API 호출 지연 시 백엔드 스레드 고갈 방지를 위해 `@Async` 비동기 분리 및 Resilience4j Circuit Breaker 적용.
5. **동시성 제어:**
    - 일일 AI 분석 요청 횟수 차감 시 Redis Redisson 분산 락을 통한 정합성 보장.

## 5. 단계별 개발 마일스톤 (Milestones)

- **Phase 1 (설계):** 웨이트/유산소 통합 DB ERD 확정, DDL 작성, BaseEntity 정의
- **Phase 2 (백엔드 코어 개발):** 음성(STT) 입력 파싱, 통합 운동 CRUD, Spring AI 다종 파싱 연동, 비즈니스 계산 로직 및 단위 테스트
- **Phase 3 (서버 배포):** Docker Compose 구성, AWS EC2 배포, Swagger 문서화
- **Phase 4 (프론트엔드 연동):** React Native (Expo) UI 구현 및 실서버 API 연동
- **Phase 5 (고도화):** RAG을 이용하여 VectorDB 기반 전문성이 추가된 대체 운동 추천 (확장)
